## 背景

前几轮全部集中在解析引擎与服务层，工具链、后台 UI 与部署形态仍停留在上游 2026-04 的状态：
Gradle 8.10 已被 Kotlin 标记为即将不支持，后台还在用 2012 年的 jQuery UI 1.8.22 与 layui 2.9.18，
运行镜像是非 LTS 的 JDK 22，生产配置里还留着明文管理员密码与三个未被引用的旧配置文件。
本轮把这些一并收口，并把「什么算做完」写进 README。

## 风险与注意事项

1. **管理员密码已更换**：迁移到 bcrypt 时工具要求 ≥12 位，因此密码必须换新。
   旧密码立即失效；新密码由本次操作生成并单独交付，不要写进仓库。
2. **Gradle 8.14 的 TLS 问题**：新 HTTP 客户端在双栈网络下会优先 IPv6，
   若 IPv6 到 Maven Central 不通，会报 `Remote host terminated the handshake`。
   已在 `gradle.properties` 用 `systemProp.java.net.preferIPv4Stack=true` 兜底。
3. **容器镜像更换**：`docker-compose.yml` 的 `image` 已改为 `eclipse-temurin:21-jre`。
   1Panel 的 App 页面如果重新下发 compose 配置，可能把镜像改回 `1panel/java:*`，
   届时需再次修改或把 `JAVA_VERSION` 对应镜像替换掉。
4. **后台 UI 升级只做了 HTTP 级验证**：5 个页面均 200、静态资源均可达、登录链路正常；
   没有做像素级视觉回归，若发现样式异常可回滚 `static/static/layui/` 与两个模板。

## 后续修复：后台错误信息区分 + 一次真实故障的诊断

### 触发

生产上「后台改任何东西保存都报错」，界面一律显示 **网络异常**，无法判断是数据库、权限还是别的。

### 诊断结论

| 怀疑对象 | 实测结果 |
|---|---|
| MySQL | **正常**。Hikari 池正常建立连接、方言识别为 MySQL、43 张表数据完好、容器到 3306 可达 |
| CSRF | **机制正常**。带 `X-CSRF-Token` 的写操作能进入业务逻辑（返回「不存在」这类业务错误），
  6 个后台页面都带 token meta |
| 业务接口 | `seachbookSource` / `seachusers` 是 `@Get`（列表），写操作是 `@Post`，参数与返回正常 |
| 应用日志 | 唯一的真实报错是 `TypeError: redeclaration of const tagKeyName`（14:49 出现 3 次），
  由某书源的登录脚本 `java.startBrowser('https://yuancang.cc/user','登陆')` 触发的 JS 求值 |

**根因**：该源在 `jsLib` 与规则脚本里**各自声明了同名顶层常量** `const tagKeyName`。规则作用域以
jsLib 作用域为 prototype，Rhino 判定 const 需要沿 prototype 链重新声明，于是抛错——这与真实 JS
环境里「两个脚本在同一全局重复声明 const」的行为一致，**责任在书源**。

引擎**不做**「把 const 偷偷改写成 var」这类兜底：那是为单个源牺牲通用语义，会把书源问题藏起来。
改为用测试把这一语义固定下来（`JsScopeSemanticsTest`）。

### 真正的问题：错误信息不可分辨

`ajax.js` 的 `error` 回调**忽略响应体**，一律 `layer.msg('网络异常')`；同时拦截器对「会话过期」
的 AJAX 请求回 **302 跳登录页**，XHR 拿到的是 HTML，前端更无从判断。于是三种完全不同的失败
（登录过期 / CSRF 失效 / 业务错误）在界面上长得一模一样。

### 修复

| 侧 | 改动 |
|---|---|
| 拦截器 | 带 `X-Requested-With` / `X-CSRF-Token` / `Accept: application/json` 的请求，未登录时回 **401 + `NEED_LOGIN: 登录已过期，请重新登录`**；普通导航仍 302 |
| 拦截器 | CSRF 失败文案改为「页面已过期或会话已重建，请刷新页面后重试」 |
| `ajax.js` | 发送 `X-Requested-With`；按 401 / 403 / 业务 `errorMsg` / HTTP 状态分别提示；401 时提示后跳登录页 |
