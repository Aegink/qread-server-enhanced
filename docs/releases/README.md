# 发布说明（releases）

本目录记录每一次对外可部署的变更。格式借鉴 `rimvoid/legado`（阅读 Archive）的发布说明实践：**每次发布一份文件，写清背景、改了什么、风险在哪、怎么验证、怎么回滚**。

## 命名与位置

```
docs/releases/<YYYY-MM-DD>-<短横线主题>.md
```

例：`docs/releases/2026-10-29-upstream-rebaseline.md`

## 必须包含的六节

1. **版本标识**：`upstream <上游tag> / <我们的提交号> / <构建日期>`；jar 大小与 SHA-256 只用于核对"是不是这一批产物"，不作为版本号。
2. **背景**：为什么发这个版本（上游同步 / 引擎移植 / 安全修复 / 运维需求）。
3. **变更**：按 `book`（引擎）/ `web`（服务层）/ 依赖与配置 / 测试 / 文档 分组，每条一句话说清"改了什么、影响谁"。
4. **风险与注意事项**：破坏性变更、需要手工操作的步骤（例如 `admin.passwordHash` 必须先生成）、需要客户端配合的行为。
5. **验证**：构建与测试结果（套件/用例数）、启动冒烟结果（`/`、`/admin`、`/api/5/appversion`、无令牌鉴权）、以及本次新增的针对性测试。
6. **回滚**：回滚到哪个提交、需要同时回滚哪些产物（`read.jar` + `libs/` + `conf/`）、以及回滚后的必查项。

## 模板

```markdown
# <标题>

- 版本标识：upstream <tag> / <commit> / <date>
- 产物：read.jar <bytes> / SHA-256 <hash>；libs/book-1.0-SNAPSHOT.jar <bytes> / SHA-256 <hash>
- 部署方式：<1Panel / 手工 java -jar / 容器>

## 背景

## 变更

### 引擎（book/）
### 服务层（src/main/kotlin）
### 依赖与配置
### 测试与文档

## 风险与注意事项

## 验证

## 回滚
```

## 约定

- 一份说明对应**一次部署**，不要把两次无关变更塞进同一份。
- 哈希变了但代码没变（重新构建）也要记录，避免下次误判"产物被换过"。
- 历史发布说明只增不改；如需更正，追加"勘误"小节。
