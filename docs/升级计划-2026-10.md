# 升级计划（2026-10 研究稿）

> 研究日期：2026-10-29。依据：两条上游的实时状态、Maven Central 最新版、OSV 漏洞库、以及本仓库与 `LegadoTeam/legado` 的函数级对照。
> 结论先行：**先做 M1（依赖安全 + 解析对齐）和 M2（引擎能力补齐），框架大版本（Solon 4 / okhttp 5 / Kotlin 2.4）单独立项，不要和引擎改动混在一次发布里。**

### 1.3 引擎能力缺口（函数级，不是行数）

**AnalyzeUrl（URL 选项）**：我们的 `UrlOption` 缺少两个上游已文档化的字段——上游 `ruleHelp.md` 明确写了
`https://www.example.com,{"timeout":5000,"followRedirects":false}`。

| 缺失 | 影响 |
|---|---|
| `timeout`（读取超时，毫秒，按链接生效） | 慢站点只能吃全局超时，容易整页超时失败 |
| `followRedirects`（是否跟随重定向） | 靠 302 做风控/Cookie 下发的站点行为与阅读客户端不一致 |
| `saveCookie` | 书源 JS 无法把请求拿到的 Cookie 手动落盘 |
| `isLoginHeaderSite`（登录头只发同站，上游 #1099 安全修复） | 登录态请求头可能被带到第三方域名 |

**AnalyzeRule**：上游有而我们没有 4 个——`getElementsRaw`（原始元素列表）、`setLocal`、`setRuleName`、`getBatchContext`（批量上下文，配合 `getElementsRaw`）。

**JsExtensions**：上游 81 个函数、我们 75 个。上游独有 18 个里，**服务端有意义**的是：`cacheContent`、`singleFlight`、`sourceConcurrencyKey`、`lock`、`tick`、`parseJsRequestHeaders`、`getSourceNavigationContext`、`functionThisObj`。

**明确不移植（Android 专属）**：`getThemeConfig`、`getThemeMode`、`getReadBookConfig`、`openVideoPlayer`、`canOpenSourceUi`、`refreshBookInfo`、`refreshBookToc`、`refreshContent`。

### 1.4 我们已有的、不要被"升级"冲掉

`usePhone`/`getusePhone`/`headusePhone`/`postusePhone`/`getVerificationCodeusePhone`、`startBrowserDp`、`getWebViewUANEW`、`qread`、`showBrowser`、`java.click`、`applyBodyJs`、`setRequestHeader`、`safeLogUrl`、`testErrorCode`、多租户 Cookie/Cache、本地书八格式、`utf8ToGbk`。

## 二、里程碑

### M1「依赖安全 + 解析对齐」（低风险，约 1 天）

- 依赖：jsoup → 1.23.2、bcpkix-jdk18on → 1.86、rhino → 1.9.2、gson → 2.15.0、sqlite-jdbc → 3.54.1.0。
- 引擎：移植 `SourceHtmlParser.parseSourceHtml`（`TagSet` + `Tag.SelfClose`，保住 `<a/>` 老写法）、`AnalyzeByJSoup` 的 `deselectAll()`。
- 引擎：`UrlOption` 增加 `timeout` / `followRedirects`，并在 `AnalyzeUrl` 里落到 OkHttp 的 `readTimeout` 与 `followRedirects`。
- 测试：新增"URL 选项 timeout/followRedirects 端到端"（本地 HTTP：一个 302 链、一个慢响应），并跑全量。
- 风险：jsoup 1.23 有 API 调整（`Element#clear` → `deselectAll` 等），编译期会暴露；现成 171 用例兜底。
- 回滚：单提交回退，产物同步回退。

### M2「引擎能力补齐」（中风险，约 1～2 天）

- `AnalyzeUrl`：`saveCookie`、`isLoginHeaderSite`（安全项，登录头限同站）。
- `AnalyzeRule`：`getElementsRaw`、`setLocal`、`setRuleName`、`getBatchContext`。
- `JsExtensions`：`cacheContent`、`singleFlight`、`sourceConcurrencyKey`、`lock`、`tick`、`parseJsRequestHeaders`；逐个函数确认服务端语义（缓存要带 `userid`、`lock`/`tick` 不能阻塞事件循环）。
- 测试：`java.saveCookie` 落盘、登录头只发同站、`singleFlight` 并发合并、`lock/tick` 超时行为。
- 风险：多租户语义（缓存/锁必须带 `userid`），必须逐个写测试而不是照抄。

### M3「框架大版本」（高风险，独立立项）

- `okhttp 5.5.1`、`json-path 3.0.0`、`kotlin 2.4.21`、`coroutines 1.11.0`（同时清掉 `build.gradle.kts` 里的 `force`），然后才是 `solon 4.1.1` + MyBatis-Plus 配套。
- 先做 okhttp/json-path/kotlin/coroutines 一批，验证通过后再动 Solon——Solon 跨大版本会影响 240 处引用与启动/路由/序列化行为，必须单独一次发布。
- 验证：全量测试 + 启动冒烟 + 真机书源抽测（本地书、RSS、段评、WebSocket 调试）。

### M4「护栏与观测」（持续）

- 书源 fixture 扩充：`usePhone` 路径、字体反混淆（QueryTTF）、段评/目录反序、编码（GBK）。
- 加一条"引擎回归真源"：把 6 个根目录书源 JSON 指向本地快照站点跑通（当前端到端用例是自建规则，不是真源规则）。
- 性能基线：整页搜索 100 并发、单机内存曲线，作为以后升级的对照。

## 三、不建议做的事

1. **不要**为追平上游而整包覆盖 `AnalyzeRule`/`AnalyzeUrl`/`JsExtensions`——我们的实现已被大幅重写，逐函数对照才安全（行数差：AnalyzeRule +160/−399、AnalyzeUrl +115/−76、JsExtensions +216/−91）。
2. **不要**动 `src/main/resources/static/*`（App 的 Flutter 产物）和 `appversion`（`3.1.0`），那是客户端契约。
3. **不要**把 Android 专属 JsExtensions 搬进来（主题、阅读配置、视频播放、界面刷新）。
4. **不要**在一次发布里同时改引擎与框架大版本——出问题无法二分定位。

## 四、需要拍板的三个问题

1. M1 是否现在就做（含 4 个 CVE 修复）？
2. M3 的边界：okhttp/json-path/kotlin/coroutines 一批先上，还是连同 Solon 4 一起上？
3. mysql-connector-j 从 9.1.0 跳到 26.x 是否需要在 M3 里做（默认 MySQL 部署需要回归，SQLite 部署不受影响）。
